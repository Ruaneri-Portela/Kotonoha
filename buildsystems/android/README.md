# Kotonoha Android

English | [Portugues (Brasil)](README.pt-BR.md)

Open this directory in Android Studio. Requirements: JDK 17 or newer
compatible with Gradle 8.14.6 (Android Studio's bundled JDK works), SDK 36,
CMake 3.22.1, NDK 28.2.13676358, Git and a vcpkg checkout.

```sh
export VCPKG_ROOT=/path/to/vcpkg
export ANDROID_HOME=/path/to/Android/sdk
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/28.2.13676358"
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew :app:assembleExampleDebug
./gradlew :app:assembleAmagamiDebug
./gradlew :app:assembleZeroNoTsukaimaDebug
./gradlew :app:assembleSnowRadishDebug
./gradlew :app:assembleDokiDokiDebug -Pabis=arm64-v8a
./gradlew :app:assembleSchoolDaysDebug
./gradlew :app:assembleRealLiveDebug
./gradlew :app:assembleSummerRadishDebug
```

On Windows, run PowerShell from the `Android` directory:

```powershell
$env:VCPKG_ROOT = 'C:\path\to\vcpkg'
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat :app:assembleExampleDebug
```

Visual Studio's bundled vcpkg also works. When launching Android Studio from
the Start menu, set `VCPKG_ROOT` in your user environment and restart Studio.
The SDK comes from `local.properties` (generated by Studio); Gradle's selected
NDK is passed to vcpkg automatically, without a separate `ANDROID_NDK_HOME`.

Each flavor has its own application ID and APK under
`app/build/outputs/apk/`. APKs include `arm64-v8a` and `x86_64` by default. Use `-Pabis=x86_64` for an emulator-only build,
or a comma-separated subset. The vcpkg triplets are `arm64-android` and
`x64-android`. Build DDLC for one ABI per APK.
Run Gradle invocations sequentially: concurrent builds share native `.cxx`
configuration directories. Multiple assemble tasks may be passed to one invocation.
Dependencies are installed into `build/vcpkg/<ABI>`; DDLC uses CPython provided by vcpkg. No macOS/iOS Python library is used by Android.

SDLActivity and native SDL use the checkout in `lib/submodules/SDL`.
The engine is packaged as `libkotonoha_engine.so`, distinct from the example's
`libKotonoha.so` even on case-insensitive filesystems.
SDL_ttf and ImGui use the other repository submodules; FFmpeg, json-c, libass,
iconv, PlutoSVG and CPython come from vcpkg.
DDLC uses a separate `build/vcpkg-python/<ABI>` install tree so other game flavors
cannot remove its CPython dependency during configuration.
Each ABI has its own installation so vcpkg cannot remove the other
architecture's libraries when configuring a dual-ABI APK.
The manifest pins `vcpkg-tool-meson` to 1.9.0#10: Meson 1.12.1 rejects Windows
installation prefixes (`C:/...`) when cross-compiling for Android.

Each APK contains engine `assets/` and its game's `game-assets/`. Gradle
stages resources, computes a content fingerprint and includes only the selected
game. BootstrapActivity extracts the APK on a worker thread before starting
SDL, displays preparation failures, and leaves settings/saves outside resources.
`-PbundleGameAssets=false` excludes local commercial game data.
Supply your own legal game data in `../games/<game>/game-assets/`; do not commit it.

Engine assets are extracted to `<dataDir>/files/assets`, game assets to
`<dataDir>/game_assets`. External game data in `Android/obb/<applicationId>`
(directly or under `game_assets`/`game-assets`) takes precedence.
Saves/settings use `Android/data/<applicationId>/files/Kotonoha/<applicationId>`.
Launcher settings store resource names and resolve them at runtime. `overlay`
is discovered automatically; a named `overlay2` may be in OBB, external app data
or private app data. See the [directory policy](../docs/Directories.pt-BR.md).
Android's scoped-storage rules
may restrict access from file managers; this project requests no broad storage
permission and does not invent an `Android/obb-data` directory.

Extracted resources have stable private paths; an APK content fingerprint
determines when to update packaged files.
Native dialogs may be unavailable on Android; the MPV inspector also offers a
bundled-shader selection list.

DDLC packages Debug Python extension modules with Debug Python, and Release modules with Release Python.
