# Kotonoha Visual Studio (Win32 / x64 / ARM64)

**English (US)** | [Português (Brasil)](README.pt-BR.md)

`Kotonoha.sln` is a **checked-in** native Visual Studio solution, structured like
the checked-in Xcode project: one project per application target, with the
game/provider/VM sources compiled directly into the executable. CMake remains
the source of truth for the source lists and the vcpkg dependencies.

## Solution layout

| Target | Kind | Notes |
|---|---|---|
| `KotonohaEngine`, `KotonohaImGui` | static libraries | shared engine/UI code |
| `KotonohaExample` + 15 game ports | applications | one per game slug |
| `KotonohaLauncher` | application | unified multi-engine launcher |
| `SDL3`, `SDL3_ttf` | imported native projects | from `lib/submodules/` |

The native SDL3 project supports Win32, x64 and ARM64. The upstream SDL3_ttf
`.vcxproj` only defines Win32/x64 configurations, so **ARM64 uses the vcpkg
SDL3/SDL3_ttf libraries** instead; the solution skips building the native
SDL3_ttf project in ARM64 configurations.

## Architectures

Win32 (x86), x64 (amd64) and ARM64 are supported, each with `Debug` and
`Release` configurations. The authoritative matrix — project list, source
counts, SDL provider per architecture and build commands — is in
[Visual Studio targets, platforms and architectures](../../docs/VISUAL_STUDIO_TARGETS.md).

## Prerequisites

- Visual Studio 2022 or newer with the Desktop development with C++ workload
  and the Windows SDK. The toolset is the installed default (`$(DefaultPlatformToolset)`).
- Git submodules initialised (`lib/submodules/SDL`, `SDL_ttf`, `imgui`).
- vcpkg manifest dependencies installed for the chosen triplet, e.g.:
  ```sh
  cmake --preset windows-x64
  ```
  The CMake presets create a complete `vcpkg_installed` tree under
  `out/build/<preset>/vcpkg_installed/`.

## Build (IDE)

Open `buildsystems/visualstudio/Kotonoha.sln`, pick a platform/configuration
in the toolbar, and build. `SDL3.dll` / `SDL3_ttf.dll` and the vcpkg runtime
DLLs are copied next to each executable automatically.

## Build (command line)

```sh
msbuild buildsystems/visualstudio/Kotonoha.sln /t:Build /p:Configuration=Debug /p:Platform=x64 ^
  /p:KotonohaVcpkgInstalled=<repo>/out/build/windows-x64/vcpkg_installed/
```

Replace `x64` with `Win32` or `ARM64` (and the triplet directory with
`x86-windows` / `arm64-windows`) for the other architectures.

`KotonohaVcpkgInstalled` is an overridable MSBuild property. It defaults to
`<repo>/vcpkg_installed/`, which may be incomplete in a working tree; point it
at the tree generated by the matching CMake preset.

## Regenerate the checked-in files

```sh
# 1. Refresh source lists from a configured CMake "Visual Studio" build tree
cmake -S . -B out/build/vsprobe-x64 -G "Visual Studio 18 2026" -A x64
python3 buildsystems/visualstudio/Scripts/generate_visualstudio.py --export-from-cmake out/build/vsprobe-x64

# 2. Rewrite Kotonoha.sln, Directory.Build.props and every .vcxproj
python3 buildsystems/visualstudio/Scripts/generate_visualstudio.py

# Read-only consistency check
python3 buildsystems/visualstudio/Scripts/generate_visualstudio.py --check
```

`Scripts/GenerateBuildVersion.py` refreshes `generated/Kotonoha/core/BuildVersion.hpp`
from Git on every build; it keeps the timestamp when metadata has not changed.

## Validation and limitations

`python3 tools/ValidateBuildMetadata.py` checks the CMake/Xcode metadata and
the Visual Studio manifest together. Commercial game data is never committed;
the game targets compile but require locally supplied assets to run.

A native WinUI 3 library/launcher is planned as an imported x64/ARM64 project —
see the [implementation plan](../../docs/WINUI_NATIVE_APP_PLAN.md).

For other platforms see [CMake](../cmake/README.md), [Xcode](../xcode/README.md),
[Android](../android/README.md) and the Windows build guides under `docs/`.
